User API Architecture

Hexagonal + DDD — Domínio isolado de FastAPI/SQLAlchemy/JWT; adapters dependem do domínio, nunca o contrário

Regra de dependência (Hexagonal)

  • • domain/ nunca importa FastAPI, SQLAlchemy, PyJWT ou argon2
  • • application/ (Use Cases) depende apenas de Ports (Protocols)
  • • adapters/ (inbound e outbound) dependem de application/domain — nunca o inverso
  • • troca de Postgres, Argon2 ou IdP não toca regra de negócio

Canal sensível (VerifyCredentials)

  • • único ponto que vê a senha em texto puro além do registro
  • • exposto só via auth service-to-service (API key/mTLS), sem ingress público
  • • resposta indistinguível para "não existe" / "senha errada" / "inativo" (FR-016)
  • • IdP externo continua sendo o único emissor/assinante de JWT
